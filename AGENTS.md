# UniSender learning loop

For substantive UniSender work, use `skills/unisender-skill-factory/SKILL.md` after the task reaches an observable outcome.

- Capture only verified, reusable solutions. Do not log routine work, speculative ideas, or failed attempts as successes.
- Store evidence in the private OS state directory selected by the skill; never copy raw evidence into this public repository.
- Abstract campaign-specific material before capture. Never publish contact data, credentials, private URLs, account identifiers, client copy, protected HTML, screenshots, or business metrics.
- Promote only when the weighted evidence gate passes. A direct user decision may allow an early proposal, but never bypasses behavioral evals, privacy checks, or release checks.
- Prefer updating the narrowest existing skill. Use semantic versioning and keep each skill's `VERSION`, `CHANGELOG.md`, and `catalog.json` entry aligned.
- Public GitHub release is within the standing scope of this repository only through a candidate PR after validation, behavioral evals, tests, and the public-data audit pass.
- This workflow never authorizes sending, scheduling, importing contacts, or changing a live UniSender campaign or automation.
